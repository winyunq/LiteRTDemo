Wrapper / C ABI / DLL

LiteRT-LM C API 与 DLL 架构

本页整理 `litert_lm_wrapper.dll` 对外暴露的稳定 C ABI。维护重点是让调用顺序、结构体字段、同步消息和推理入口可以被快速定位；如果只需要蓝图调用，请从主手册进入 Unreal 插件章节。

推荐阅读顺序 先确认后端与模型路径，再创建 Engine 和 Conversation，最后追加消息并运行推理。 核心入口：LiteRtLm_RunInference

Lifecycle

最小调用链

1. 查询后端 LiteRtLm_GetAvailableBackends
2. 创建引擎 LiteRtLm_CreateEngine
3. 创建会话 LiteRtLm_CreateConversation
4. 追加消息 AppendUserMessage
5. 执行推理 LiteRtLm_RunInference
6. 释放资源 DestroyConversation

Data Contract

结构体与回调

LiteRtLm_Config 模型路径、后端、设备、LoRA、视觉与音频模型路径等初始化参数。 LiteRtLm_SamplingParams 温度、Top-K、Top-P、随机种子和最大输出长度等采样参数。 LiteRtLm_Result 同步调用结果，包含错误码、错误文本和可释放的返回缓冲区。 LiteRtLmCallback 流式 Token、错误、完成状态和用户上下文指针的回调协议。

Function Index

函数索引

阶段API用途
初始化LiteRtLm_CreateEngine根据 `LiteRtLm_Config` 加载模型并创建引擎句柄。
初始化LiteRtLm_CreateConversationWithConfig创建带自定义参数的 Conversation。
消息LiteRtLm_AppendUserMessage追加用户消息，适合文本与多模态输入封装前的常规路径。
消息LiteRtLm_AppendMessageJson追加符合 chat schema 的 JSON 消息数组。
消息LiteRtLm_AppendAssistantMessage追加历史助手消息，用于恢复上下文或记录工具调用结果。
推理LiteRtLm_RunInference驱动生成并通过回调返回流式结果。
推理LiteRtLm_StopMessage请求中止当前生成。
推理LiteRtLm_WaitUntilDone在同步场景中等待当前生成完成。
销毁LiteRtLm_DestroyConversation释放会话句柄。
销毁LiteRtLm_DestroyEngine释放引擎句柄和底层资源。
