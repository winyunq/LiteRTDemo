Deep diving into the 100% official native C++ source code to analyze the dynamic Host-side Tensor allocation and runtime graph matching mechanisms of LiteRT/TFLite vision feature extractors.

1. Official Native Dynamic Patchify Mechanism

In the pristine official preprocessor implementation (located in stb_image_preprocessor.cc under PatchifyImage), the system dynamically calculates the actual number of patches num_patches based on physical image dimensions:

graph TD Raw[Physical Input Image] -->|Dynamic H/W Splitting| Patches["Calculate actual patches (num_patches)"] Patches -->|On-demand Allocation| Alloc["CreateManagedHostMemory( {batch_size, num_patches, patch_dim} )"] Alloc -->|Zero Padding-free Delivery| Engine[LiteRT Vision Feature Extractor]

Under this elegant mechanism, the system strictly avoids allocating unnecessary dummy slots for `max_num_patches = 2520`, which greatly optimizes memory footprints and perfectly matches the dynamic tensor contracts of the graph.

3. Advanced Engineering Breakthroughs: Lifetime Security & Tensor Dimension Limits

3.1 Exterminating Cross-DLL Asynchronous Lambda Dangling Pointers

In previous attempts, the wrapper generated transient stack-allocated std::string buffers inside the asynchronous Lambda closure for SendMessageAsync. Although the c_str() pointers were passed to Unreal, the strings themselves were immediately destructed upon Lambda exit. Under heavy multi-threaded vision prefill operations, this introduced severe dangling pointers, resulting in **100% reproducible Windows Access Violation segmentation faults (exit code 1)**.

The Winyunq Solution:

We resolved this by introducing **physically persistent callback buffers** (e.g., cb_text_buffer) inside the heap-allocated LiteRtLm_ConversationContext. Because the context remains alive throughout the session, the buffers are guaranteed to survive 100% intact, securing absolute memory safety for Unreal.

3.2 Static TFLite Graph Dimension Constraints & Enforced Resizing

Empirical testing revealed a major contract constraint of the static TFLite Graph. No matter how aggressively we physically downsampled the input image (e.g., to 256x144 using GDI+), the official preprocessor stb_image_preprocessor.cc **unconditionally upscale-resized the image to 1056x576, generating exactly 2376 patches**.

Consequently, vision prefill execution is highly sensitive to the stability of LiteRT's static graph layout compilers on Windows, frequently hitting library-level `Assertion Failed` panics. This discovery provides essential, concrete guidance for future upgrades of TFLite's internal Windows runtimes.
