Operation 05 / Hardware Defense

Hardware Telemetry

DXGI real-time polling and system fallback discipline

Sequence / Hardware telemetry polling
            sequenceDiagram
                participant HUD as UI/HUD (Level 3)
                participant SUB as Subsystem (Level 2)
                participant DX as DXGI Driver (Kernel)

                loop Every 1.0 second
                    HUD->>SUB: 1. QueryAvailableVramMB()
                    SUB->>DX: 2. Query physical budget
                    DX-->>SUB: 3. Return actual available VRAM
                    SUB-->>HUD: 4. Return int32 (MB)
                    alt VRAM is safe
                        HUD->>HUD: Show green indicator
                    else VRAM is low
                        HUD->>HUD: Trigger fallback or warning
                    end
                end
01 / Operational actions
Action A: Real-time sampling

Call QueryAvailableVramMB from HUD or monitoring UI code. Internally, the plugin uses DXGI on Windows so the query stays lightweight and does not block the render pipeline.

Action B: Physical fallback

When available VRAM drops below a project-defined threshold, stop issuing new LoadModel calls and fall back to a smaller context or the cpu backend.

02 / Source demo
// Standard telemetry pattern (DemoTavernHUD.cpp)
void ADemoTavernHUD::UpdateStats() {
    int32 Vram = ULiteRtLmSubsystem::QueryAvailableVramMB();

    StatusText = FString::Printf(TEXT("VRAM: %d MB"), Vram);
}
