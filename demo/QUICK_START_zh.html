01

运行前检查

先排除路径、模型和显存问题，后面蓝图调试会简单很多。

引擎版本

项目当前绑定 UE 5.7。换引擎版本后，先重新生成项目文件并编译 Editor Target。

模型路径

默认模型目录是 Content/Models。建议项目路径不要包含中文字符，避免底层 mmap 路径问题。

显存配置

自动配置会查询可用 VRAM。低显存机器可降低 MaxNumTokens 或改用 cpu 后端。

03

蓝图接入方式

新增节点都在 LiteRT-LM 分类下，同名 DisplayName 用来模拟重载体验。

方案 A：函数库节点，适合 Level Blueprint / Widget 
Event BeginPlay
  -> Load LiteRT-LM Model
     ModelFileName = "gemma-4-E2B-it.litertlm"
     bUseAutoConfig = true

On Send Button Clicked
  -> Send LiteRT-LM Chat Request
     UserMessage = InputText
     SessionOwner = Self
     OnChunk: Append Text
     OnDone: Enable Send Button
方案 B：组件节点，适合 NPC / Actor 
LiteRtLmComponent
  SystemPrompt = "你是酒馆老板。"
  SamplingParams.MaxTokens = 256

绑定：
  OnTextChunkReceived -> 更新字幕
  OnInferenceCompleted -> 记录结果

调用：
  Send LiteRT-LM Chat Message
  Send LiteRT-LM Chat Message + Sampling Params
节点 用途 常用输入
Load LiteRT-LM Model 加载模型，支持 Config、绝对路径、项目 Models 文件名三种输入。 ModelFileName、bUseAutoConfig、Backend
Send LiteRT-LM Chat Request 发送普通文本、系统提示词、多模态路径或 OpenAI 风格 JSON 消息。 UserMessage、SystemPrompt、ImagePath、MessagesJson
Make LiteRT-LM Sampling Params 构造单次请求的温度、TopP、TopK、最大生成 Token、约束解码参数。 Temperature、MaxTokens、ConstraintType
Release LiteRT-LM Session 清空某个 SessionOwner 对应的会话和 KV Cache。 SessionOwner，通常传 Actor、Widget 或 Self。
04

JSON / Tools 请求示例

需要完整历史或工具调用时，使用 JSON 版本的聊天请求节点。

MessagesJson

[
  {
    "role": "system",
    "content": "你是一个简洁的游戏 NPC。"
  },
  {
    "role": "user",
    "content": "给我一句酒馆老板的欢迎词。"
  }
]

ToolsJson

[
  {
    "name": "set_npc_mood",
    "description": "设置 NPC 情绪",
    "parameters": {
      "type": "object",
      "properties": {
        "mood": { "type": "string" }
      }
    }
  }
]
05

常见问题

优先按这里排查，能覆盖大多数 Demo 接入问题。

现象 优先检查
模型加载失败 确认 ModelPath 是真实文件；优先用 Resolve LiteRT-LM Model Path 检查路径。
首次请求卡顿 首次会创建引擎、加载权重和预热 GPU。可以在加载界面提前调用加载节点。
第二个 NPC 串记忆 给不同 NPC 传不同 SessionOwner。同一个对象会复用同一份会话缓存。
显存不足 改用自动配置、降低 MaxNumTokens，或把 Backend 改成 cpu。
需要重置对话 组件用 ResetConversation；函数库用 Release LiteRT-LM Session。
