LiteRTDemo AI 狼人杀蓝图升级方案

本文档用于把当前 LiteRTDemo 从“本地 LLM 对话演示”升级为“AI 狼人杀教学 Demo”。当前阶段先做设计和蓝图实施说明；等 UMG MCP 可用后，再按本文档中的资产清单和任务拆分去生成或编辑 Widget / 蓝图资产。

1. 当前项目判断

结论：你的记忆基本正确。当前 LiteRTDemo 是一个轻量的本地 LLM 对话场景，而不是完整游戏玩法。

当前可复用基础如下：

| 模块 | 现状 | 对狼人杀升级的价值 |

| --- | --- | --- |

| `Content/Demo.umap` | Demo 关卡 | 可以作为首个 AI 狼人杀测试关卡的起点。 |

| `AWinyunqDemoGameMode` | BeginPlay 时创建 `UWinyunqMcpWrapper` 并显示聊天 UI | 可替换或派生为狼人杀专用 `BP_WW_GameMode`。 |

| `ADemoTavernHUD` | 绘制 LiteRT-LM 性能监控 | 可保留为 Debug HUD，显示当前 AI、延迟、tokens/s、VRAM。 |

| `UWinyunqDialogueWidget` | C++ UMG 对话组件，监听流式 chunk 和完成回调 | 可作为“聊天记录/流式输出”逻辑参考。 |

| `ULiteRtLmComponent` | 可挂到 Actor 上的 AI Brain 组件 | 最适合挂在每个 AI 玩家 Actor 上，天然隔离 Session。 |

| `ULiteRtLmBlueprintLibrary` | 已提供蓝图可调用的加载模型、发送请求、采样参数、释放会话等节点 | 支持蓝图优先实现，不需要先写完整 C++。 |

插件更新状态：

- `Plugins/LiteRT-LM-Unreal` 是 submodule。

- 已执行 `git -C Plugins\LiteRT-LM-Unreal pull --ff-only`。

- 插件 `master` 当前结果是 `Already up to date`。

- 当前插件工作树在 `8eefbd0 Add Blueprint chat helpers and multimodal config`，主项目记录的 submodule 指针仍是 `3e3ce70`，所以主仓会继续显示 `Plugins/LiteRT-LM-Unreal` 为 modified。这是 submodule 指针差异，不是插件内部脏文件。

2. 目标定位

本 Demo 的目标不是先做商业级狼人杀，而是做一个可学习、可调试、可逐步扩展的 AI 游戏样例。

第一版目标：

1. 单机本地运行。

2. 一名人类玩家可以作为玩家或旁观主持。

3. 5 到 7 名 AI 玩家由 LiteRT-LM 驱动。

4. 游戏规则由蓝图状态机强约束，AI 只返回“发言、投票、夜间行动意图”。

5. UI 展示角色、天黑/天亮流程、发言记录、投票、夜间结果、胜负。

6. Debug 面板展示每个 AI 的 prompt、原始输出、解析结果、延迟和 token 统计。

非目标：

- 第一版不做联网多人。

- 第一版不让 AI 直接修改游戏状态。

- 第一版不依赖 UMG MCP 编辑蓝图资产；等 MCP 可用后再自动化创建 UI。

- 第一版不追求复杂扩展角色，先把核心循环跑通。

3. 推荐 MVP 规则

建议从 6 人入门局开始：

| 人数 | 阵营与角色 |

| --- | --- |

| 2 狼人 | 夜间共同选择击杀目标，白天伪装发言并投票。 |

| 1 预言家 | 夜间查验一名玩家阵营。 |

| 1 女巫 | 夜间拥有一次解药和一次毒药；MVP 可先只做解药，再加毒药。 |

| 2 平民 | 只有白天发言和投票能力。 |

胜利条件：

- 狼人胜利：狼人数量大于或等于好人数量，或所有神职死亡。

- 好人胜利：所有狼人死亡。

为了教学清晰，第一版建议固定座位数量和角色配置，后续再做房间配置 UI。

6. LiteRT-LM 蓝图接入

6.1 模型加载

推荐在 `BP_WW_GameMode::BeginPlay` 或未来的 `BP_WW_GameInstance` 中加载一次模型：


Event BeginPlay
  -> Load LiteRT-LM Model
     ModelFileName = 当前 Content/Models 内实际模型文件名
     bUseAutoConfig = true
     Backend = "gpu"
     MaxNumTokens = 2048 到 4096
     bEnableStreaming = true

当前仓库里 `Content/Models/` 已有模型缓存文件。实际蓝图节点里优先使用 `Resolve LiteRT-LM Model Path` 检查最终路径，再调用 `Load LiteRT-LM Model`。

6.2 SessionOwner 规则

每个 AI 玩家必须使用不同的 `SessionOwner`：

- 如果使用 `ULiteRtLmComponent`，组件内部以自身作为 session key，适合 NPC / AI 玩家。

- 如果使用 `ULiteRtLmBlueprintLibrary.SendLiteRtLmJsonChat`，`SessionOwner` 传 `BP_WW_PlayerAgent` 或该 Agent 上的专用 `Object`。

不要所有 AI 都传 `Self` 指向同一个 `GameMode`，否则多个玩家会共享同一段 KV cache，容易出现串记忆。

6.3 请求队列

本地模型推理应先按串行队列执行，保证稳定可复现：


BP_WW_AIRequestQueue
  PendingRequests: Array<FWWAIRequest>
  bBusy: bool

EnqueueRequest(Request)
  Add PendingRequests
  TryStartNext

TryStartNext
  if bBusy return
  if PendingRequests empty return
  bBusy = true
  CurrentRequest = PopFirst
  BuildPrompt
  Send LiteRT-LM Chat Request

OnChunk(TextChunk)
  Append to CurrentStreamingText
  Broadcast Debug Update

OnDone(Result)
  Parse Result.FullText or Result.FullJson into FWWAIDecision
  Send decision back to BP_WW_RoundManager
  bBusy = false
  TryStartNext

6.4 采样参数

不同阶段使用不同采样：

| 场景 | Temperature | MaxTokens | 说明 |

| --- | --- | --- | --- |

| 夜间行动 | 0.2 到 0.4 | 96 到 160 | 更稳定，减少胡乱选目标。 |

| 白天发言 | 0.7 到 0.9 | 160 到 320 | 更像人，有策略和情绪。 |

| 投票 | 0.3 到 0.5 | 96 到 160 | 需要理由，但结果要明确。 |

| 记忆摘要 | 0.2 | 160 到 256 | 需要压缩事实，不要发挥。 |

如果使用 `Make LiteRT-LM Sampling Params`，结构化输出时可把 `ConstraintType` 设为 `Json`。如果蓝图端 JSON 解析能力不足，建议后续补一个很薄的 Blueprint Function Library，只负责把 JSON 字符串解析为 `FWWAIDecision`，其他玩法仍放在蓝图里。

7. Prompt 设计

7.1 Prompt 分层

每次请求组合以下片段：

1. 规则身份：你正在扮演狼人杀中的某个玩家。

2. 私密信息：你的角色、阵营、已知同伴、夜间查验结果、药水状态。

3. 公开信息：座位、存活、公开发言、投票、死亡结果。

4. 性格参数：谨慎/激进/爱诈身份/沉默/爱归票。

5. 当前任务：发言、投票、夜间行动。

6. 输出格式：必须按指定 JSON 返回。

7.2 夜间行动 Prompt 示例


你是狼人杀玩家 P{SeatId}，角色是 {RoleName}。
当前阶段：{PhaseName}，第 {DayNumber} 夜。

你的私密信息：
{PrivateInfo}

当前公开信息：
{PublicState}

最近公开发言：
{RecentTranscript}

任务：
根据你的角色执行本阶段可用行动。你只能选择仍然存活的合法目标。
不要解释规则，不要输出多余文本。

输出 JSON：
{
  "action": "kill|check|save|poison|skip",
  "targetSeatId": 0,
  "reason": "一句话说明原因",
  "confidence": 0.0
}

7.3 白天发言 Prompt 示例


你是狼人杀玩家 P{SeatId}，角色是 {RoleName}。
你需要在白天公开发言。其他玩家不知道你的真实身份，除非你主动跳身份。

你的目标：
- 如果你是好人：找出狼人并说服其他人。
- 如果你是狼人：隐藏身份，误导投票，但不要过于离谱。

公开信息：
{PublicState}

你的私密记忆：
{PrivateMemory}

最近发言：
{RecentTranscript}

输出 JSON：
{
  "speech": "你要公开说出的话，第一人称，80字以内",
  "claimRole": "none|seer|witch|villager",
  "accuseSeatId": 0,
  "defendSeatId": 0,
  "reason": "你的真实策略说明，仅用于调试"
}

注意：`reason` 只进 Debug，不进入公共发言。

7.4 投票 Prompt 示例


当前进入投票阶段。你必须从存活玩家中选择一名投票目标，不能投自己。

公开信息：
{PublicState}

最近讨论：
{RecentTranscript}

你的私密目标：
{PrivateGoal}

输出 JSON：
{
  "voteTargetSeatId": 0,
  "publicReason": "公开投票理由，40字以内",
  "privateReason": "真实理由，仅调试"
}

8. 规则状态机

`BP_WW_RoundManager` 是唯一能推进阶段和修改游戏结果的对象。AI 返回的是意图，RoundManager 负责合法性校验。

8.1 初始化


StartNewGame
  Read DA_WW_RuleConfig
  Spawn BP_WW_PlayerAgent x PlayerCount
  Assign SeatId
  Shuffle Roles
  Assign PrivateState
  Give werewolves KnownWerewolfSeatIds
  Broadcast "游戏开始"
  SetPhase NightStart

8.2 夜间流程


NightStart
  DayNumber += 1
  Clear NightResult
  SetPhase NightWerewolves

NightWerewolves
  Ask all alive werewolves for kill target
  Resolve by majority or first valid target
  Set NightResult.KilledSeatId
  SetPhase NightSeer

NightSeer
  Ask alive seer for check target
  Store private result to SeerKnownResults
  SetPhase NightWitch

NightWitch
  If witch alive and has antidote, ask save/skip
  Later add poison decision
  Apply final death result
  SetPhase Dawn

8.3 白天流程


Dawn
  Broadcast night death result
  CheckVictory
  if not over SetPhase DayDiscussion

DayDiscussion
  For each alive player in seat order:
    if human -> wait for input
    if AI -> enqueue DaySpeech
    Append public speech to chat log
  SetPhase DayVote

DayVote
  For each alive player:
    collect vote
  Count votes
  Exile highest voted player
  SetPhase Exile

Exile
  Reveal or hide role based on config
  CheckVictory
  if not over SetPhase NightStart

8.4 合法性校验

每个 AI 决策都必须经过校验：

- 目标是否存在。

- 目标是否存活。

- 是否允许选择自己。

- 当前阶段是否允许此角色行动。

- 女巫是否还有药。

- 狼人击杀是否至少有一名狼人存活。

非法输出处理：

1. 尝试从文本中提取合法目标。

2. 若失败，按默认策略选择随机合法目标。

3. 在 Debug 面板记录 `bParsedOk = false` 和原始输出。

9. UI 设计

第一版 UI 应该偏工具化，方便学习和调试：


WBP_WW_HUD
  Top: WBP_WW_PhaseBanner
  Left: WBP_WW_SeatList
  Center: WBP_WW_ChatLog
  Right: WBP_WW_ActionPanel
  Bottom: Human input / Continue button
  Optional overlay: WBP_WW_DebugPanel

交互要求：

- 白天阶段，人类玩家可输入公开发言。

- 投票阶段，人类玩家从存活玩家列表中选择目标。

- 夜间阶段，如果人类玩家有角色能力，只显示合法行动按钮。

- AI 正在生成时，SeatCard 显示“思考中”。

- 每条发言记录标记阶段和说话人。

- Debug 面板可开关，不打扰普通玩法。

10. 蓝图实现顺序

建议严格按这个顺序做，避免 UI 做完后规则无法驱动。

M0 文档与资源整理

- 建立本文档。

- 确认插件蓝图节点可见。

- 确认模型能在当前 Demo 中加载。

M1 无 AI 的规则骨架

- 创建 `BP_WW_RoundManager`。

- 创建 Enum / Struct。

- 用固定假数据跑通阶段切换。

- 用 Print String 或简单 Widget 显示阶段。

验收：

- 点击开始后可以从夜晚走到白天、投票、放逐、胜负检查。

M2 玩家 Agent 与 UI

- 创建 `BP_WW_PlayerAgent`。

- 创建 `WBP_WW_HUD`、`SeatList`、`ChatLog`、`ActionPanel`。

- RoundManager 广播事件，UI 订阅刷新。

验收：

- 能看到 6 个座位、角色仅自己可见、公开日志追加正常。

M3 AI 请求队列

- 创建 `BP_WW_AIRequestQueue`。

- 接入 `Send LiteRT-LM Chat Request`。

- 实现 OnChunk / OnDone。

- 先只让 AI 输出白天发言。

验收：

- AI 玩家按座位顺序依次发言，不会并发打乱。

M4 夜间行动与投票

- 添加狼人击杀。

- 添加预言家查验。

- 添加女巫解药。

- 添加 AI 投票。

验收：

- 一局可以自动跑到胜负。

M5 Debug 与教学化

- Debug Panel 显示 prompt、raw output、parsed decision、tokens/s。

- 增加“一步一步推进”按钮。

- 增加“自动运行到下一阶段”按钮。

验收：

- 用户能看懂 AI 每一步为什么这么做，并能定位解析失败。

M6 UMG MCP 自动化资产编辑

等 UMG MCP 可用后再做：

- 生成/调整 `WBP_WW_HUD`。

- 批量绑定控件命名。

- 创建 SeatCard 变体。

- 生成 Debug Panel 的可折叠视图。

- 根据本文档更新蓝图节点布局。

12. 测试清单

基础测试：

- 模型能加载，失败时 UI 有错误提示。

- 6 名玩家生成，角色数量正确。

- 狼人知道同伴，好人不知道狼人。

- 预言家查验结果只给预言家。

- 女巫药水使用后不会重复出现。

- AI 发言进入公共日志。

- AI 投票目标合法。

- 放逐后玩家不再参与夜间和白天行动。

- 胜利条件能结束游戏。

稳定性测试：

- AI 输出空文本时不会卡死。

- AI 输出非法 JSON 时有 fallback。

- 队列中途失败时会继续下一请求。

- 重开一局时所有 AI Session 被释放。

- 长局时会压缩历史，prompt 不无限增长。

教学测试：

- Debug Panel 能看到 prompt。

- 能单步推进阶段。

- 能看见每个 AI 的原始输出和解析结果。

- 能解释为什么某个 AI 投票给某人。

13. 风险与处理策略

| 风险 | 处理 |

| --- | --- |

| 本地模型生成慢 | 串行队列加 UI 思考状态；MVP 限制发言字数和 token。 |

| AI 不按格式输出 | 使用 JSON 约束；失败时 fallback；Debug 记录原始输出。 |

| 蓝图 JSON 解析不方便 | 玩法保持蓝图，必要时补一个小型 JSON 解析 Function Library。 |

| 多 AI 串记忆 | 每个 AI 使用独立 `SessionOwner` 或独立 `LiteRtLmComponent`。 |

| prompt 泄露隐藏身份 | PromptBuilder 严格区分公开状态和私密状态。 |

| 规则被 AI 幻觉带偏 | RoundManager 权威校验，AI 只返回意图。 |

| 上下文越来越长 | 每天结束后生成私密 memory summary，公共日志只保留最近 N 条。 |

14. 下一步建议

下一次实际动手时，建议不要先做 UI。先创建 `BP_WW_RoundManager`、Enum、Struct 和一套 Print String 驱动的状态机。只要无 AI 规则骨架跑通，后续接 LiteRT-LM 和 UMG MCP 都会简单很多。

推荐第一批落地任务：

1. 新建狼人杀 Enum / Struct。

2. 新建 `BP_WW_RoundManager`，用假玩家跑通阶段。

3. 新建 `BP_WW_AIRequestQueue`，只接白天 AI 发言。

4. 用现有 `ADemoTavernHUD` 或简单 Widget 显示调试信息。

5. UMG MCP 可用后，再按第 11 节拆分生成 UI。
