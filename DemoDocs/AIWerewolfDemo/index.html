项目定位

当前 Demo 是本地 LLM 对话场景；AI 狼人杀将作为项目级玩法 Demo，文档和页面部署在 DemoDocs/AIWerewolfDemo。

不混入插件文档

Document/ 保留给 LiteRT-LM 插件文档，本页只描述 LiteRTDemo 的玩法升级。

蓝图优先

规则、阶段、UI 绑定和 AI 调度尽量用蓝图表达，必要时只补薄 C++ 辅助。

可调试

每个 AI 请求都保留 prompt、raw output、解析结果和性能数据。

MVP 规则

第一版建议固定 6 人局，先跑通核心循环，再扩展配置和复杂角色。

角色数量职责
狼人2夜间共同击杀，白天隐藏身份并误导投票。
预言家1夜间查验一名玩家阵营。
女巫1MVP 先做解药，后续加毒药。
平民2白天发言和投票。

蓝图架构

BP_WW_RoundManager 是规则权威；AI 只能返回意图，不能直接修改游戏状态。

BP_WW_GameMode

创建局、加载模型、生成玩家 Agent、创建 HUD。

BP_WW_RoundManager

推进夜晚、白天、投票、放逐和胜负检查。

BP_WW_AIRequestQueue

串行调度 LiteRT-LM 请求，处理 chunk 和 done 回调。

BP_WW_PlayerAgent

表示一个座位上的玩家；AI 玩家挂 LiteRtLmComponent。

数据结构

公开状态和私密状态分离，Prompt Builder 只给 AI 合法可知的信息。

类型建议内容
EWWPhaseBoot, Lobby, AssignRoles, NightStart, NightWerewolves, NightSeer, NightWitch, Dawn, DayDiscussion, DayVote, Exile, CheckVictory, GameOver
FWWPlayerPublicStateSeatId, DisplayName, AliveState, bIsHuman, LastVoteTargetSeatId, PublicClaims
FWWPlayerPrivateStateRole, Team, KnownWerewolfSeatIds, SeerKnownResults, WitchHasAntidote, PrivateMemory
FWWAIDecisionRequestType, ActorSeatId, TargetSeatId, SpeechText, Reason, Confidence, RawText, bParsedOk

LiteRT-LM 接入

每个 AI 玩家使用独立 SessionOwner，并通过请求队列串行调用本地模型。

请求队列

EnqueueRequest
  Add PendingRequests
  TryStartNext

TryStartNext
  if bBusy return
  BuildPrompt
  Send LiteRT-LM Chat Request

OnDone
  Parse FWWAIDecision
  Return to RoundManager
  TryStartNext

输出格式

{
  "speech": "我觉得 P1 的发言不自然",
  "claimRole": "none",
  "accuseSeatId": 1,
  "defendSeatId": 0,
  "reason": "P1 试图快速归票"
}

状态机

先用假玩家跑通规则骨架，再接入 LiteRT-LM 和 UMG。

01

StartNewGame

生成玩家、洗角色、写入私密状态，进入夜晚。

02

Night

狼人击杀、预言家查验、女巫救人，RoundManager 校验所有目标。

03

Dawn

公布夜间结果，检查胜负，进入白天讨论。

04

DayDiscussion

存活玩家按座位顺序发言；AI 发言由请求队列生成。

05

DayVote

收集投票，放逐最高票玩家，再次检查胜负。

UMG MCP 后续任务

UMG MCP 可用后，只让它按资产小步创建和调整 UI，不一次性生成完整游戏。

HUD

创建 WBP_WW_HUD，放置阶段、座位、日志、操作区和 Debug 插槽。

SeatCard

绑定玩家名、座位号、存活状态、票数和 AI 思考状态。

DebugPanel

展示 prompt、原始输出、解析结果和性能数据。

里程碑
